# 업스트림 변경점 분석 (rebase 델타)

기존 분석 문서 7편(01~07)이 작성된 시점 이후, upstream `continuedev/continue` 에서
일어난 변경을 정리한 문서. **기존 문서 중 사실관계가 바뀐 부분을 짚는 것이 목적**이다.

- 작성일: 2026-08-25
- 최종 수정일: 2026-08-25
- 근거 등급: 이 문서의 모든 항목은 ✅ **확인** — 저장소 코드/커밋을 직접 대조해 확인했다.
  웹 검색이나 릴리즈 노트가 아니라 `git diff` 결과가 출처다.

---

## 결론 (먼저 읽을 것)

1. **`continuedev/continue` 저장소는 더 이상 유지보수되지 않는다.**
   README 에 `The continuedev/continue repository is no longer actively maintained and is read-only for all users.`
   라고 명시되어 있다. 마지막 커밋은 2026-07-20 이다.
   → hdsp-agent 는 Continue 를 **"움직이는 참조 대상"이 아니라 "고정된 설계 레퍼런스"로** 다뤄야 한다.

2. **2.0.0 최종 릴리즈에서 서버 의존 계층이 통째로 제거됐다.**
   control plane(Hub), continue-proxy, 인증(WorkOS), 익명 텔레메트리(PostHog·Sentry),
   무료 체험/크레딧, 원격 세션, 백그라운드 에이전트가 모두 삭제됐다.
   결과적으로 Continue 는 **로컬 전용 구조**가 됐다.
   → hdsp-agent 입장에서는 오히려 **참고하기 쉬워졌다.** 기존 문서가 "이 계층은 무시해도 된다"고
   에둘러 설명하던 부분이 실제로 코드에서 사라졌다.

3. **기존 문서 7편 중 04(도구 시스템)가 가장 크게 깨졌다.**
   `GetTool` 이 동기→비동기로 바뀌었고 `callTool` 반환형이 바뀌었다. 두 가지 모두 breaking change 다.
   02(LLM 통합), 03(프로토콜), 06(에이전트 모드)은 부분 수정이 필요하고,
   05(컨텍스트 제공자)와 01(개요)은 영향이 작다.

4. **기존 문서가 인용한 파일 경로 40개 중 3개는 처음부터 존재하지 않았다.** (§6 참조)
   업스트림에서 삭제된 것이 아니라, 작성 당시에도 없던 경로다.

### 3.3 `04-도구-시스템.md` — **가장 크게 깨짐. 재작성 권장**

**(a) `GetTool` 이 비동기가 됐다 — breaking**
```diff
- export type GetTool = (params: ConfigDependentToolParams) => Tool;
+ export type GetTool = (params: ConfigDependentToolParams) => Promise<Tool>;
```
도구 정의가 이제 IDE 에 I/O 를 할 수 있다. 실제 사용 예가 `readSkill` 이다 —
정의 시점에 `loadMarkdownSkills(params.ide)` 로 스킬 목록을 읽어 **description 에 끼워 넣는다.**
즉 도구 설명이 런타임에 동적으로 조립된다.

**(b) `ConfigDependentToolParams` 변경 — breaking**
```diff
- isSignedIn: boolean;
+ ide: IDE;
```
로그인 개념이 사라졌고, 대신 IDE 핸들이 들어왔다. (a)와 한 쌍이다.

**(c) `callTool` 반환형 변경 — breaking**
```diff
- ): Promise<ContextItem[]>
+ ): Promise<{ contextItems: ContextItem[]; mcpUiState?: McpUiState }>
```
기존 문서 04 §4 의 실행 파이프라인 코드 예시는 이 시그니처 기준으로 전부 갱신해야 한다.

**(d) 도구 오버라이드 신설 — `core/tools/applyToolOverrides.ts` (신규 69줄)**
설정(YAML)에서 내장 도구의 프롬프트를 갈아끼우거나 아예 끌 수 있다.
오버라이드 가능 필드: `description`, `displayTitle`, `wouldLikeTo`, `isCurrently`, `hasAlready`,
`systemMessageDescription`(prefix / exampleArgs), `disabled`.
없는 도구 이름을 지정하면 fatal 이 아닌 `ConfigValidationError` 로 수집되고 계속 진행한다.

> hdsp-agent 관점: **도구 프롬프트를 코드 밖으로 빼는 패턴**이다. 도구 로직과 도구 설명 문구의
> 수명 주기가 다르다는 인식이 반영돼 있다. 참고할 가치가 있다.

**(e) `read_skill` 도구 신규**
`BuiltInToolNames.ReadSkill = "read_skill"`. `readonly: true`, `isInstant: true`.
마크다운 스킬 파일을 이름으로 읽어온다. 저장소 루트에 `skills/` 디렉토리도 생겼다.

**(f) 인자 파싱 강화 — `core/tools/parseArgs.ts` (+49)**
- `toolCall.function.arguments` 가 이미 객체면 파싱을 건너뛴다
- `coerceArgsToSchema()` 신규: **`JSON.parse()` 가 문자열 안의 JSON 까지 깊게 파싱해 버리는 문제**를
  스키마 대조로 되돌린다. `.json` 파일 내용을 인자로 넘길 때 문자열이어야 할 값이 객체가 되던 버그.
  `callTool` 이 MCP 호출 직전에 이 함수를 태운다.

**(g) `runTerminalCommand` 대폭 수정 (+148/−17)**
- **기본 타임아웃 2분** 신설 (`DEFAULT_TOOL_TIMEOUT_MS = 120_000`), `waitForCompletion` 모드에서 적용.
  SIGTERM 후 일정 시간 뒤 SIGKILL 로 승격.
- `childProc.killed` 를 살아있음 판정에 쓰지 않는다 — kill() 호출 여부일 뿐 종료 여부가 아니다.
  `exitCode === null && signalCode === null` 로 판정.
- **원격 워크스페이스 정책 반전**:
  `ENABLED_FOR_REMOTES = ["", "local", "wsl", "dev-container", "ssh-remote", ...]`
  → `LOCAL_ONLY = ["", "local"]`.
  이유가 주석에 있다 — `childProcess.spawn()` 은 확장 호스트에서 실행되는데 확장 호스트는 거의 항상
  로컬이므로, 원격 워크스페이스에서는 엉뚱한 머신에서 명령이 돌거나 ENOENT 가 났다.
  이제 모든 원격 타입은 `ide.runCommand()` 로 위임한다.
- 작업 디렉토리 해석 분리 (`resolveWorkingDirectory`), `vscode-remote://` 스킴 처리 추가

**(h) `ToolPolicy` 타입 이동**
`@continuedev/terminal-security` 패키지에서 import 하도록 바뀌었다.
(패키지 자체는 이전 base 에도 존재했다 — 신규 패키지가 아니라 의존 방향이 정리된 것이다.)

**(i) `Tool.mcpMeta?: McpToolMeta` 추가** — MCP UI 리소스 URI 를 담는다 (§3.4).

| 터미널 도구 원격 정책 단순화(로컬만 spawn) | 원격 환경 성능은 `ide.runCommand()` 경유로 느려질 가능성 (미측정) |
| 도구 정의 비동기화 → 동적 도구 설명 가능 | 도구 로딩 경로 전체가 async 전파, 구현 복잡도 상승 |
